# Tomoyo 长期演进蓝图与迭代计划 (Long-Term Roadmap)

> **定位与基线**：`v1.0.1` 已完成主链路闭环（休眠态 Working Set `1.07–1.46 MB`、Private Commit `20.31 MB`、100 轮压测句柄零增长、Everything 1.4/1.5a 原生 IPC 修复、设置中心受控组件与双层校验、ClearType 原生字形清晰度修复）。  
> **演进原则**：坚持 Windows 原生一等公民定位，以「检索准确率、日常高频效率、交互细节稳定、严守内存与句柄预算」为衡量标准，避免为了功能堆砌牺牲响应速度或常驻占用。

---

## 一、现状诊断与核心判断

结合 `v1.0.1` 代码实现与实机使用反馈，后续投入产出比最高的演进方向集中在五个维度：

| 维度 | 当前实现状态 (`v1.0.1`) | 核心短板与体验天花板 | 演进目标 |
|---|---|---|---|
| **1. 检索相关性与可解释性** | 已有拼音/首字母匹配（`matcher.rs`）、全局 `Frecency`（`frecency.rs`）与 Everything 路径权重 | ① `Frecency` 仅按 `item_id` 计数，未绑定查询词，短词盲打易受全局高频项干扰；② 无命中字符高亮，用户难以理解模糊/拼音命中的原因；③ 中文多音字与空格多词联合检索未支持；④ 应用与 Everything 对桌面快捷方式未做规范化去重 | 查询词绑定习惯记忆、标题命中区间高亮、多音字与多词交集匹配、跨源去重、空输入高频直达 |
| **2. 预览与高频办公文件** | `preview.rs` 仅支持纯文本（8 KB）、目录与 PNG 缩略图 | JPG/WebP/BMP/GIF、PDF、Office（`.docx`/`.xlsx`/`.pptx`）、压缩包（`.zip`）均退化为“二进制占位提示”，右侧预览面板利用率偏低 | 零重依赖扩展全格式图片（Win32 WIC）、Office XML 摘要、ZIP 目录树与 PDF 基础信息预览，保持有界 I/O 与休眠零残留 |
| **3. 原生 UI/UX 与受控配置** | 主窗口 SDF+ClearType GDI 渲染清晰；设置中心已完成核心受控组件化 | ① 分组筛选栏不显示各分类实时命中数；② 空结果态缺少一键网页搜索/纠错引导；③ `snippets.toml`、Everything 收藏筛选器仍需手改文件；④ 缺少配置备份恢复与界面内诊断日志查看 | 筛选栏实时计数、空态回退动作、快捷键直达次级动作、设置中心补齐片段/收藏可视化受控管理与配置导入导出 |
| **4. 插件体系实用化** | 三层运行时（STDIO/WASM/WebView）、权限审批与 CLI 已就绪 | 仅有 5 个参考/内置插件；插件缺少声明式受控设置面板（Schema-driven Settings），异常/超时提示偏静默 | 插件声明式设置表单、常用离线效率插件包（WASM 优先）、插件超时/崩溃可视化提示与开发热重载 |
| **5. 工程质量与分发信任** | 112 个文件 ≤ 450 行、严格内存门禁、Windows/Linux/macOS CI 齐备 | 缺少检索排序黄金测试集、UI 主题与多 DPI 离线渲染回归对比、配置清洗模糊测试；安装包尚无代码签名与 Winget/Scoop 正式上架 | 排序黄金基准、离屏渲染快照校验、Fuzz 单测常态化，推进 Scoop/Winget 清单提交与签名分发 |

## 三、分阶段迭代计划

### 阶段一：`v1.1.0` — 检索体验跃升与视觉细节闭环（已完成）
**目标**：让日常高频检索做到「输 2–3 个字符直接回车命中」且结果一目了然。

1. **查询词绑定习惯记忆（Query-Aware Frecency）** — ✅ 已实现
   - 升级 `crates/tomoyo-core/src/frecency.rs`：保留全局使用频率的同时，增加有界映射 `(normalized_query -> item_id -> score)`（上限 400 查询词 × 8 项，14 天半衰期）；
   - 输入 `as` 选过 `Android Studio` 或输入 `1118` 选过 `DeskBox\其他\1118` 后，下次输入相同短词稳定置顶，不误伤其他查询。
2. **匹配命中字符高亮与结果可解释性** — ✅ 已实现
   - 新增 `crates/tomoyo-core/src/matcher_highlight.rs` 返回 UTF-8 安全的标题命中字节区间（覆盖精确、拼音、多音字、英文首字母与子序列）；
   - 在 `gdi.rs` / `gdi_pass.rs` 使用 `draw_text_highlighted_gdi` 以主题强调色高亮命中区段（严格维持 `FW_NORMAL`，零伪粗体）。
3. **多音字支持、空格多词交集与跨源去重** — ✅ 已实现
   - `IndexedText` 启用 `pinyin` `heteronym` 支持受限多音字组合与空格多词跨字段交集匹配；
   - `engine_rank.rs` 合并 `Apps` 与 `Everything` 时按规范化启动路径去重。
4. **分组筛选栏计数与空结果/空输入体验** — ✅ 已实现
   - 筛选栏标签展示分类实时命中数（`FilterCounts`），同步更新点击热区；
   - 空输入框按 `Frecency` 优先展示常用应用并标记「常用」；
   - 全局无本地结果时自动提供默认搜索引擎查询与 `f ` Everything 全盘搜索回退项；
   - 支持 `Ctrl+Enter`（定位所在目录）、`Shift+Enter`（文件/目录在此处打开终端，应用复制路径）。
5. **排序黄金测试集（Golden Ranking Benchmark）** — ✅ 已实现
   - 在 `crates/tomoyo-providers/tests/ranking_golden.rs` 建立查询词记忆、跨源去重、多音字、多词高亮与零结果回退回归用例集。

### 阶段二：`v1.2.0` — 办公与媒体预览增强 + 设置中心完整性补齐
**目标**：提升文件查找后的即时判断效率，消除仍需手改配置文件的遗留入口。

1. **零重依赖全格式预览增强（`crates/tomoyo-core/src/preview.rs`）**
   - **全格式图片缩略图**：调用 Windows 原生 WIC（`IWICImagingFactory`）在后台线程解码 `JPG / PNG / WebP / BMP / GIF / ICO`，按预览区尺寸等比缩放后输出有界 RGBA，休眠自动释放（不增加二进制体积）；
   - **压缩包与 Office 文档摘要**：复用已有纯 Rust `pkg_zip` + `flate2`，受限读取 `.zip` 文件清单（前 25 项）、`.docx` 段落前 20 行、`.xlsx` 工作表名称与前若干行单元格文本、`.pptx` 幻灯片标题；
   - **PDF 基础元信息**：轻量解析 PDF 头部版本、页数与文档标题，严格限制单次读盘字节上限。
2. **设置中心受控组件完整覆盖**
   - 新增「代码片段与收藏筛选」标签页：对 `snippets.toml` 与 Everything 收藏（`@today/@large/@code`）提供受控表格、标签选择、动态占位符插入下拉框与实时校验；
   - 新增 **下拉搜索框（Searchable Combobox）** 组件落盘（覆盖多选项场景，如应用屏蔽列表、剪贴板过滤或字体/语言选择）；
   - 新增配置备份/导出与带 `sanitize_config()` 预检的导入能力；
   - 新增只读诊断日志面板（查看 `tomoyo.log` 最近记录、`last_crash.txt` 与一键复制排障信息）；
   - 新增字体显示密度档位（紧凑 / 标准 / 舒适），同步作用于主窗口 `FontPack` 与行高。

### 阶段三：`v1.3.0` — 实用插件生态与开发者工具链
**目标**：从“具备插件能力”演进为“开箱即用、低内存、安全可控的轻量工具集”。

1. **插件声明式受控配置（Schema-Driven Plugin Settings）**
   - 在 `tomoyo-protocol` 扩展 `manifest.json` 的 `settings_schema`（仅允许 `bool`、`select`、`range`、`folder`、`validated_text` 等受控类型，直接复用 `UI_DESIGN_STANDARDS.md` 规范）；
   - 设置中心自动为每个已安装插件生成参数配置与权限审计面板。
2. **官方精选离线 WASM 插件集（0 常驻、按需加载、空闲回收）**
   - 时间戳 / ISO / 时区 / Cron 表达式解析器；
   - 编解码与摘要工具（URL / Base64 / Hex / JWT / UUID / 哈希）；
   - 颜色空间转换（HEX / RGB / HSL / 对比度检测）与字节/长度/温度单位换算；
   - 本地开发端口占用查询与清理（配合权限审批）。
3. **插件可观测性与开发体验**
   - 插件执行超时、非零退出、WASM 燃料耗尽或超出内存上限时，在主列表给出清晰的错误卡片与日志入口；
   - `tomoyo-cli dev <plugin-dir>` 监听源码变更并向运行中的 Tomoyo 发送热重载信号。

### 阶段四：`v1.4.0` — 视觉渲染深化、自动化质量门禁与分发成熟
**目标**：建立面向长期维护的自动化质量防线与标准软件分发渠道。

1. **原生视觉与输入法体验深化**
   - 优化主输入框在高 DPI 与中文 IME 候选框定位下的细节表现，支持更柔和的窗口阴影与 Windows 11 系统主题自动跟随（`跟随系统 / 浅色 / 深色 / 午夜蓝`）；
   - 支持空输入框按 `↑` 回溯近期搜索词，支持常用结果自定义固定别名（Alias）。
2. **自动化视觉与鲁棒性回归门禁**
   - 离屏渲染回归测试：无头生成浅色/深色/午夜蓝 × `100% / 150% DPI` 的 DIB 快照并校验布局边界、文字不截断、零句柄增长；
   - 对 `sanitize_config()`、Everything 二进制线协议解析器与 `pkg_zip` 引入属性/模糊测试（Property / Fuzz Tests）。
3. **正规分发与信任度建设**
   - 完善并提交 Winget (`winget-pkgs`) 与 Scoop 正式清单，持续跟随 GitHub Release 自动化校验；
   - 评估接入开源免费代码签名方案（如 SignPath 等）消除 Windows SmartScreen 首次拦截提示；
   - 保持 `tomoyo-ui-macos` / `tomoyo-ui-linux` 跨平台适配层与核心引擎同步演进，不破坏 Windows 主线资源预算。

## 四、持续推进与门禁机制

每个迭代版本（`v1.1.0` → `v1.2.0` → `v1.3.0` → `v1.4.0`）按以下固定节奏小步闭环推进：

1. **单需求切片**：每次 PR/提交聚焦单一明确目标，变更后立即执行本地验证；
2. **四项强制门禁**：
   - `pwsh -File scripts/check_hygiene.ps1`（全仓每文件 ≤ 450 行、零重型禁用依赖、零 D2D/WARP）；
   - `RUSTFLAGS="-D warnings" cargo test --workspace`（全平台零警告，含新增排序黄金用例与配置清洗单测）；
   - `tomoyo.exe --self-test --strict-budget`（休眠 WS ≤ 2.0 MB、Private ≤ 28.0 MB、100 轮压测 GDI/USER `+0`）；
   - `WinSta0\Default` 实机交互验收（Everything 实测、设置中心受控组件与主界面字体渲染检查）；
3. **版本发布闭环**：验证通过后合入 `main`、打 Tag 触发 GitHub Actions CI + Release、SHA-256 校验安装包并在本机完成覆盖升级与桌面实测。
